# 舱单数据定义

id是主单、分组单或箱货明细唯一字符串编号，parent为空表示主单。节点申报件数、净重和毛重是其完整子树的申报总量，校验时只加直接子节点，避免多层重复计数。包装carton=1件，pallet=10件；重量kg与t统一为kg。件数必须非负整数，净重非负且毛重不得低于净重。
拆并结构采用每节点最多一个父级的有向图；自环、长环、缺父级均阻断封存，保留环路径。不会以平面求和替代逐层校验。
危险品按明确分类与UN编号检查，3类与5.1类禁止同箱；未知分类和缺失编号需复核。此演示规则只覆盖文中三类，不替代运输合规审批。
报关总量只汇总主单，与context.json内的申报件数、净重和毛重逐项比较。重复同值折叠，重复编号冲突全部隔离。原始计数=采纳+隔离+空行+重复表头+重复同值行。
封存需所有图、重量、危险品和采信问题处理完毕。数值均Decimal，对外字符串保留精度，编号不转整数。

## 箱号继承回单

回单是批次之上的独立业务动作（不进入七段管线，不改批号）。输入三段：`source_containers`（至少两只申报原箱）、`terminal.containers` 与 `terminal.seals`（码头沿用旧箱号及逐箱封签）、`receipt`（船公司回执编号、重贴新箱号及件数/净重/毛重合计）。形状问题直接422；业务阻断写入回单 `block_codes`，稳定码见 reasons.INHERITANCE_BLOCKS。

`master_lines` 每张受影响主单一行，含原箱号、件数、净重、毛重、原箱封签、唯一最终箱号与追踪状态；`source_totals` 为逐主单合计（主单节点即完整子树申报量，不跨层重复加），`receipt_totals` 为回执合计，差异进入 RECEIPT_TOTAL_MISMATCH。`recheck_findings` 是拆并后受影响子树的逐层核对结果。`verdict` 分别给申报侧、码头侧、船公司侧的闭合/阻断结论。

回单持久化在 `inheritance_receipts` 表，只追加不删除。`(run_id,idempotency_key)` 唯一：同键重试不新增第二套，同键内容冲突409。`current` 以并箱事件 `merge_key` 为粒度，仅已确认回单可置当前，阻断回单只留痕；回滚把当前下线并恢复指定或最近一版已确认旧版，全部历史行与原箱封签证据保留。封存导出包新增 `inheritance_receipts.json`，只含当前生效回单。
